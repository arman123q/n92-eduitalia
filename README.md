# N92 Edu-Italia — Website

Premium, eligibility-first website for N92 Edu-Italia (study-in-Italy consultancy
for Indian students and parents). Built with Next.js + TypeScript, exported as
static files, deployable to Cloudflare Pages at zero recurring cost.

## Build status

- **Stage 3 — DONE:** design system (forest green #103F35, champagne gold
  #C7A05A, ivory #FAF9F5; Playfair Display + Inter), responsive shell, original
  logo used as-is, accessible navigation (desktop + mobile), footer with
  official sources.
- **Stage 4 — DONE:** complete 4-step eligibility assessment — validation,
  back/next, progress indicator, answers preserved in the browser session,
  transparent rules engine (`lib/eligibility.js`, unit-tested), preliminary
  results shown **before** any contact request, optional lead form.
- **Lead mode — DEMO:** no database is connected yet (by design at this
  stage). The form states clearly that submissions are stored only in the
  visitor's browser and are **not sent**. The Supabase schema for the later
  backend stage is in `supabase/leads.sql`; configuration placeholders are in
  `.env.example`.
- **Stage 5 — DONE:** cinematic Three.js hero (`components/Hero3D.tsx`) — fully
  procedural Venetian canal scene (animated water, facade-textured buildings,
  campanile + dome silhouettes, golden "journey" path with a travelling light,
  gold-dust particles), restrained pointer/scroll camera, lazy-loaded as a
  separate ~503 KB chunk (initial load unchanged), DPR capped, pauses when
  hidden/off-screen. Fallbacks: reduced-motion, no-WebGL and chunk-failure all
  fall back to the Stage 3 CSS/SVG skyline; the eligibility form never depends
  on it. **Not visually verified in a real browser** (no local-browser access
  to localhost in this environment) — first real-device check still pending.
- **Not yet built:** Stage 6 (university/course directory,
  scholarships directory, cost calculator), Stage 7 (guidance counsellor),
  Stage 8 (live lead backend + admin).

## Run locally

```bash
npm install
npm run dev        # development server
npm run build      # production build → static export in out/
npm test           # unit tests for the eligibility rules engine
```

## Deploy (Cloudflare Pages)

- Framework preset: Next.js (static export) — or serve the `out/` folder as
  static assets.
- Build command: `npm run build` · Output directory: `out`
- Environment variables (later stage only): see `.env.example`.

## Honesty rules baked into this codebase

- No invented admission probabilities, scholarship amounts, deadlines or
  tuition figures. Data entries must carry an official source URL and a
  last-verified date.
- Assessment results are always labelled **preliminary**.
- The guidance assistant (later stage) is a deterministic FAQ/guidance tool
  and is never labelled as an AI model.
- The original N92 logo file (`public/logo.jpg`) is used exactly as supplied.

## Final Master Specification build (from 30 Oct 2026)

The project now implements the FINAL MASTER SPECIFICATION in phases.
`docs/IMPLEMENTATION_PLAN.md` records the architecture decisions.

**Phase 2 — public website (done):** 20 routes — home, /study-in-italy,
/universities (+ detail), /courses (+ detail, shortlist, compare up to 3),
/scholarships (+ detail), /calculator (editable assumptions, low/typical/high
scenarios, EUR+INR, print), /eligibility, /process, /documents (interactive
checklist), /visa-guide, /resources, /faq, /about, /contact, /privacy,
/terms, custom 404. Navigation matches the owner's UI reference (logo used
as-is; Book Consultation CTA). A rules-based **Guidance Assistant** (clearly
labelled "not an AI model") answers from published FAQ knowledge.

**Data layer (`lib/data.ts`):** the site reads published records from
Supabase at runtime when configured; until then it uses the bundled starter
dataset (`data/seed.json`: 10 universities, 13 courses, 4 scholarships,
10 FAQs — all honestly labelled with verification status and official
sources) and directories visibly show a "Starter dataset" notice. No record
invents fees, deadlines or amounts ("Not verified — check official page").

**Phase 3 — database (prepared, awaiting owner project):**
- `supabase/schema.sql` — full schema (profiles, site_content,
  content_versions, universities, courses, scholarships,
  calculator_settings, faqs, leads, audit_log) with RLS: anon reads
  PUBLISHED only + inserts leads only; authenticated admin manages content;
  a `media` Storage bucket (public read, admin write).
- `supabase/seed.sql` — generated by `node scripts/gen-seed-sql.mjs`.
- `scripts/test-rls.mjs` — 7 live probes to run with the anon key after
  setup (published-only reads, draft invisibility, write blocks, lead
  insert allowed, leads unreadable to public).
- Setup: owner creates the Supabase project → runs schema.sql, then
  seed.sql → creates the admin user in Auth → turns OFF public sign-ups →
  sets NEXT_PUBLIC_SUPABASE_URL / NEXT_PUBLIC_SUPABASE_ANON_KEY (see
  `.env.example`; the service-role key is never used by the site).

**Tests:** 15/15 unit tests (eligibility engine + calculator maths).
Production build passes; all routes verified in the static export.
Still NOT verified in a real browser (localhost limitation) — the 3D hero
and click-throughs get verified after public deployment, as with the
IELTSwithKaif go-live.

**Phase 4–6 — Admin Dashboard, CMS & CRM (code complete; activates when
Supabase is connected):** `/admin` — Supabase Auth login (with password-reset
email), protected by RLS (the page being hidden is NOT the security; the
database rules are). Sections:
- **Dashboard** — live counts from the database (enquiries, new/follow-up
  leads, published records, scholarships needing review) + recent enquiries.
- **Universities / Courses / Scholarships / FAQs** — full visual CRUD:
  search, add/edit forms with friendly controls (checkbox chips for levels
  and subjects, one-per-line document lists), publish/unpublish, delete with
  confirmation, verification-status warnings, and an automatic rollback
  snapshot + audit-log entry on every change.
- **Website Content** — edit the homepage hero text and section on/off
  toggles as drafts, publish when ready, restore earlier published versions.
  The homepage reads the published content live (built-in copy is the
  fallback until first publish).
- **Calculator Settings** — edit all default assumptions with explanations.
- **Student Leads (CRM)** — search/filter, open a lead, change follow-up
  status, set follow-up dates, assign, add internal notes, CSV export,
  delete. In demo mode (no database) it honestly shows only this browser's
  test enquiries, clearly labelled.
- **Media Library** — image upload to the `media` bucket (images only,
  5 MB cap), preview grid, copy public URL, delete with warning.

Until the database is connected, admin sections show a clear "not
connected" notice instead of fake data.
